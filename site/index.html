An agent that can spend your money — without being trusted with it.

Gatekeeper proves an investor is eligible without seeing their identity, then enforces their spending mandate inside a TEE. The agent never holds the credentials, and it cannot widen its own limits. One compiled Rust decide() serves the CLI, the console, the MCP server, the A2A endpoint and the enclave — so every surface gives the same verdict.

Use it

Three ways in, none of them a fork. Every command below is in the repo's package.json.

Serve the gate over MCP

Eight tools, stdio or Streamable HTTP. gate_evaluate answers from the contract's own compiled logic — the registered wasm component, hosted in JavaScript — so it needs no Rust toolchain, no Terminal 3 account, and nothing online.

git clone https://github.com/PugarHuda/t3-gatekeeper-agent
cd t3-gatekeeper-agent/agent && npm ci
npm run mcp          # stdio server; npm run demo:mcp drives it
# optional: the Rust host build adds credential-binding + idempotency checks
#   cd ../gate-contract && cargo build --bin gate_cli --release
// any MCP host: Claude Code, Claude Desktop, Cursor …
{ "mcpServers": { "gatekeeper": {
    "command": "node",
    "args": ["<repo>/agent/src/mcp-server.mjs"] } } }

Talk to it over A2A v1.0

JSON-RPC on the official @a2a-js/sdk. Discover the card, SendMessage, read the task back. Every request must carry a Web Bot Auth signature, resolved from your published key directory.

cd agent && npm run a2a      # :41241 by default (A2A_PORT)
curl -s localhost:41241/.well-known/agent-card.json
POST /   A2A-Version: 1.0 · Signature, Signature-Input, Signature-Agent
{ "jsonrpc": "2.0", "id": 1, "method": "SendMessage",
  "params": { "message": { "role": "user", "parts": [{ "data": {
    "action": { "kind": "rwa.buy", "asset": "USDC", "amount_cents": 100000,
                "counterparty": "did:t3n:meridian-fund" },
    "mandate": { "max_amount_cents": 500000,
                 "allowed_assets": ["USDC"], "allowed_kinds": ["rwa.buy"],
                 "allowed_counterparties": ["did:t3n:meridian-fund"] }
  } }] } } }

Resolve it on chain, or check it offline

ERC-8004 agent #201 on the reference IdentityRegistry. The token's URI resolves to the registration file on this site, which names the token back. No wallet needed to read it.

cd agent
npm run erc8004              # owner, URI, registration doc, reputation
npm run discover             # what the node runs (scoped agent key)
node verify.mjs              # 298 checks, no API key, no credits

The problem

Private-credit funds can only sell to accredited investors — and proving it costs everyone.

A fund like Meridian Private Credit is legally barred from selling to a non-accredited buyer. Today that means collecting passports, bank statements and net-worth attestations from every investor, then storing them: a compliance cost for the fund and a breach liability that grows with every new client. And when an investor delegates buying to an AI agent, the agent is handed the account credentials and trusted to stay within its limits.

Who this is for: tokenised RWA and private-credit distribution platforms, and the treasury or wealth agents that transact with them.

Investor delegates a mandate→ Agent proves eligibility (BBS+)→ Enclave enforces the mandate→ Order leaves the TEE, signed

The fund learns exactly one fact — this buyer is accredited — and never the net worth behind it. The mandate lives in the enclave's key-value store, so the agent cannot raise its own ceiling: the decision and the outbound order are the same enclave call, and a rejected action never reaches the network.

Endpoints this site serves

All static, all read by a test in the suite.

  • /.well-known/agent-card.jsonapplication/json A2A v1.0 agent card — skills, security schemes, the JSON-RPC interface.
  • /.well-known/erc8004-registration.jsonapplication/json ERC-8004 registration-v1 document; the on-chain URI of agent #201 points here.
  • /.well-known/http-message-signatures-directoryhttp-message-signatures-directory+json Web Bot Auth key directory — the public key every outbound request is signed with.
  • /.well-known/security.txttext/plain RFC 9116 — where to report a security issue, and until when this file is valid.
  • /status/revocation.jsonapplication/json W3C Bitstring Status List, 131,072 entries; credential revocation with no chain.
